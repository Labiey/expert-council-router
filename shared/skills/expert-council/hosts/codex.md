## Codex and non-push MCP completion behavior

After dispatching the complete batch and finishing independent work, call `expert_wait` once with the execution IDs, normally using `mode: "all"`, or `"any"` only when one early result can advance the task. Set an explicit finite `timeoutMs` from the expected remaining work. Blocking in this call is intentional: it keeps the host turn alive without polling or spending Main Agent tokens. If the bounded wait expires, reassess before waiting again, then retrieve reported executions with `expert_result`.

Choose `expert_delegate.timeoutMs` for every assignment from its expected difficulty. Give potentially blocking Bash, PowerShell, and MCP calls an explicit finite, difficulty-based timeout whenever their schemas support one. The Codex MCP transport ceiling is only a safety envelope and must not be treated as the operation's execution budget.

Treat missing registered `expert_*` MCP tools as a Codex plugin load failure. Do not locate or launch the bundled server through Bash or PowerShell, send JSON-RPC manually, or substitute the CLI for a missing MCP tool. Stop before council work, report that the plugin's MCP server is unavailable, and ask the user to reinstall if necessary, fully restart Codex Desktop, and retry in a new task. A loaded Skill by itself does not prove that the MCP tools are ready.

The bundled server derives its allowed workspace boundary from the current Codex task's MCP file roots when available. For Codex versions that do not implement MCP roots, the trusted bundled `PreToolUse` hook records the current session `cwd` immediately before an Expert Council call; the server accepts only the record for the matching Codex session ID. Its plugin installation directory is never the repository workspace. Normally omit `workspace` so the selected local project root is used. Supply it only for a verified path inside one of the trusted current-task roots, never for the plugin cache. If neither channel supplies a root, report that the bundled workspace hook must be reviewed and trusted, or that the operator must explicitly configure `EXPERT_COUNCIL_WORKSPACE`; do not ask for broad filesystem access.
